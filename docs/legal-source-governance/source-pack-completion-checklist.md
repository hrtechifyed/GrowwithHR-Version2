# Legal source-pack completion checklist

A legal feature remains blocked until every applicable item is complete. An official file is not automatically an approved product rule or an approved RAG source.

## Scope and facts

- [ ] Feature scope and jurisdiction are defined.
- [ ] The exact legal question and intended deterministic statuses are defined.
- [ ] Required assessment facts are identified.
- [ ] Missing facts produce `more-information-needed` or `specialist-review`.
- [ ] Total company headcount is not silently reused as a law-specific or per-location count.

## Source identity and currency

- [ ] Official source files are collected.
- [ ] Official record and direct PDF URLs are verified.
- [ ] Document title issuer type jurisdiction and publication date are recorded.
- [ ] Commencement and effective dates are recorded.
- [ ] Amendments state variations and supersession are checked.
- [ ] One authoritative Drive file exists per source.
- [ ] Stable file naming is used.
- [ ] SHA-256 byte length and page count are recorded.
- [ ] Uncertain or superseded material is excluded from current retrieval.

## Register and mapping

- [ ] Source Register v2 row is complete.
- [ ] Existing POSH Source IDs remain unchanged.
- [ ] Exact sections and PDF pages are mapped.
- [ ] Feature IDs and proposed rule IDs are recorded.
- [ ] Reason codes and explanation topics are mapped.
- [ ] Customer wording limitations and prohibited claims are recorded.
- [ ] Internal self-review is complete.

## Review and RAG approval

- [ ] Qualified legal review is recorded.
- [ ] Reviewer scope conditions date and next review date are recorded.
- [ ] RAG approval references the exact source ID file hash and section scope.
- [ ] Only curated source chunks are created.
- [ ] Internal research is not cited as legal authority.
- [ ] Raw case data assessment answers and unapproved commentary are excluded.

## Implementation boundaries

- [ ] Deterministic rules run before retrieval.
- [ ] Retrieval cannot fill missing facts.
- [ ] Retrieval cannot alter result status reason code fingerprint or review status.
- [ ] The explanation provider cannot alter deterministic output.
- [ ] Provider requests contain no sensitive complaint content or raw assessment data.
- [ ] Stable report PDF email and storage contracts are unchanged unless separately approved.
- [ ] Shared resolver and panel patterns are used rather than feature-specific copies.

## Validation and release

- [ ] Schema and source cross-reference checks pass.
- [ ] Deterministic boundary tests pass.
- [ ] Retrieval boundary tests pass.
- [ ] Provider contract tests pass.
- [ ] Endpoint validation passes.
- [ ] UI wording and privacy checks pass.
- [ ] Full repository and browser regressions pass.
- [ ] Drive register project status and changelog agree with GitHub.
- [ ] Feature Coverage Registry status is updated only after all gates pass.
- [ ] Next review date and event-driven triggers are recorded.

## Immediate Phase 0 completion evidence

- [ ] Live Drive master files are confirmed before duplicate cleanup.
- [ ] Project status and changelog reflect the current POSH and operational explanation implementation.
- [ ] Source Register v2 is approved with the three existing POSH Source IDs preserved.
- [ ] The legacy Legal Rule Audit is retained as a dated snapshot.
- [ ] The 18-feature legal review register is created.
- [ ] The remaining-POSH section map is verified against exact registered files.
- [ ] The 2016 terminology amendment decision is recorded.
- [ ] New POSH assessment facts and privacy boundaries are approved.
- [ ] Limited-scope legal review is complete before an implementation PR is opened.
